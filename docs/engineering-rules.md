# Engineering Rules

Current policy for changing Sweepr: safety rules, compatibility, CI and release. [Development pitfalls](development-pitfalls.md) explains the failure mechanisms behind several of these rules.

## Project

Sweepr is a free, open-source, terminal-first Windows maintenance CLI: PowerShell 5.1 scripts (`sweepr.ps1`, `bin/*.ps1`, `lib/**`), two Go TUIs (`cmd/analyze`, `cmd/status`) and the `sw.exe` launcher (`cmd/sw`). It is GPL-3.0. Safety matters more than speed: a cleanup that deletes the wrong thing costs more than one that skips.

- Commands: `sw` and `sweepr` (`sw.exe`, `sw.cmd`, `sweepr.cmd`). Folders: `%LOCALAPPDATA%\Programs\sweepr-cli`, `~\.config\sweepr`, `~\.cache\sweepr`. Updates come from `brummilab/sweepr`, branch `main`.
- `main` is the only long-lived branch. Push directly to `main`; CI runs on every push and PR to `main`.
- `README.md` is German and is updated with every change. The CLI itself, code comments and the other docs stay English. There are no translated README copies.

## Development notes

Read [development pitfalls](development-pitfalls.md) only when working on the matching PowerShell, launcher, Git, asynchronous TUI or Windows test boundary. Current policy stays in this guide; the reference explains failure mechanisms and points to regression tests. Add only a verified, non-obvious lesson, preferably under an existing topic.

Interactive size lists use `Format-SizeListEntry` for display-cell truncation and padding; .NET format widths and Windows ConsoleHost's width helper do not reliably count CJK cells. Store app display sizes use their read-only measurement, never deletion snapshots or elevated access. Neither a display measurement nor its cache grants deletion authority. Regression and ordinary-user evidence are in the development record.

## Commands

```powershell
.\scripts\test.ps1                 # Pester tests and Go tests
Invoke-Pester -Path .\tests        # PowerShell tests only
go test ./cmd/...                  # Go tests only
go build -o bin\analyze.exe .\cmd\analyze
go build -o bin\status.exe .\cmd\status
$env:SWEEPR_DRY_RUN = "1"; .\sweepr.ps1 clean   # preview, no changes
.\sweepr.ps1 clean --dry-run
```

Off Windows, `GOOS=windows go build ./cmd/...` and `gofmt -l cmd` check the Go side; PowerShell behavior needs Windows.

## Safety Rules

- Delete only through `Remove-SafeItem`, `Remove-SafeItems`, `Remove-SafeDirectoryTree`, `Remove-OldFiles` and `Clear-DirectoryContents` in `lib/core/file_ops.ps1`. They go through `Test-SafePath` (protected paths and the whitelist) and honor dry-run mode. A raw `Remove-Item -Recurse -Force` is flagged by the Validation workflow.
- `Test-SwProtectedPath` in `lib/core/base.ps1` fails closed: an empty or unparsable path counts as protected. Keep it that way.
- `$script:ProtectedPaths` (system roots such as `C:\Windows` and `C:\Program Files`) are protected with everything below them; `$script:ExactProtectedPaths` protects the user profile root itself while still allowing targeted cache cleanup under it. Add to these lists, never route around them.
- Every command that deletes or uninstalls (`clean`, `uninstall`, `purge`, `optimize`) only reports in dry-run mode, whether set by `--dry-run` or `SWEEPR_DRY_RUN=1`. `uninstall --dry-run` names the uninstaller it would run and starts none; `tests/DryRun.Tests.ps1` mocks `Invoke-SweeprUninstallProcess` and `Remove-AppxPackage` to fail if called.
- `~\.config\sweepr\operations.log` answers which command changed which path, when, and whether it went to the Recycle Bin. `Remove-SafeItem` and `Remove-SafeItems` append each real removal, recycle and failure (a partial folder with how many entries went and where it stopped), and a folder refused before anything was removed as `SKIPPED` with its reason, which `sw history` counts as skipped, `sw uninstall` each app outcome with its install folder, registry key and uninstaller command, `sw optimize` one `OPTIMIZED` or `FAILED` row per state change (Optimize-Volume, DNS flush, ARP clear, sfc), and `sw analyze` (Go, `cmd/analyze/oplog.go`) `RECYCLED`, `FAILED`, or `REMOVED` when the Recycle Bin did not grow after the shell's too-large prompt. All use one line format with control characters escaped and the run from `_SWEEPR_OPLOG_RUN_COMMAND` / `_SWEEPR_OPLOG_RUN_ID`. Dry runs write nothing, `SWEEPR_NO_OPLOG=1` turns it off, a write failure never fails the removal (a held file is retried, a lost line goes to `--debug`), the log moves to `.old` past 5 MB, and `sw remove` keeps `operations.log*` when it deletes the config folder. Owner-cache commands record one `OWNER` outcome with the resolved root and command, or `FAILED` when incomplete, including whether `taskkill` confirmed process-tree termination, failed, or timed out; a successful command does not imply any particular file was removed. A new deletion sink records through the same format. Locked by the `Operation log` cases in `tests/Core.Tests.ps1`, `tests/Optimize.Tests.ps1`, `tests/Install.Tests.ps1` and `cmd/analyze/oplog_test.go`.
- The bulk delete helpers write nothing to the pipeline and count dry-run results too, so the clean summary and `clean-list.txt` match the preview. A caller that ignores `Remove-SafeItem`'s boolean assigns it to `$null`.
- `%LOCALAPPDATA%\Sweepr` is reserved for app data and never used as an install folder. New installs default to `%LOCALAPPDATA%\Programs\sweepr-cli`; an existing source install there keeps updating in place. `install.ps1 -Uninstall` removes only listed top-level files and the exact nested files from `Get-SweeprInstallNestedFiles`, retains unknown files and nonempty Git metadata, refuses an unrecognized install, and never falls back to another folder. After a removal it also deletes `~\.cache\sweepr` without following links, so `sw remove` and a direct `install.ps1 -Uninstall` leave the same state; `tests/Install.Tests.ps1` locks this.
- `-GameMedia` never selects generic `Pictures\Screenshots` or `Videos\Screen Recordings`; age does not prove that personal media is disposable. Existing app/game-specific opt-in targets keep their separate policy.
- Windows Update inspection queries only the local catalog in a bounded job. An incomplete, failed or timed-out query is unknown, never zero updates; stop and remove the owned job on every exit. Do not make maintenance previews wait for an online update search. Locked by `tests/Optimize.Tests.ps1`.
- The native spinner writes Unicode through `WriteConsoleW` on a real console, preserving the user's code page. Keep redirected output and explicit `Console.SetOut` capture working; do not repair missing Braille by changing global encoding. The console-buffer regression in `tests/UI.Tests.ps1` exercises the actual glyphs.
- SFC redirects stdout to a uniquely created temporary file, deletes only that file in `finally`, and records success only with both a zero native exit code and a recognized result. Unknown/localized output points to CBS.log without claiming success.
- Self-removal checks the native launcher is not in use before modifying PATH, shortcuts or files. A running `sw.exe` cannot remove itself synchronously on Windows; give the quoted PowerShell removal command instead of scheduling detached deletion. Reject linked config roots and ancestors before enumeration and before each top-level removal, while preserving operation logs.
- Package-manager installs are never removed or updated by deleting their files. `sw update` and `sw remove` recognize a winget or Scoop install folder and print that manager's own command (`winget upgrade brummilab.Sweepr`, `scoop update sweepr`, `winget uninstall brummilab.Sweepr`, `scoop uninstall sweepr`); package-manager guidance precedes the Git prerequisite. Locked by `tests/InstallLifecycle.Tests.ps1`.
- Automatic update notices query the installation's own channel in a short-lived background process, cache successful lookups for one day and failed attempts for one hour, and never install anything. Keep redirected output, help/version, structured output and dry runs free of notices and lookup writes. GitHub tags must be stable `V<version>-windows` tags; release titles are not versions. Locked by `tests/SwUpdateCheck.Tests.ps1`.
- Application cache cleanup keeps Poetry virtualenvs and Service Worker CacheStorage. Use `Clear-SweeprAppCache` for the browser, Teams, editor and notes cache leaves it owns: running or unknown owners and held/unknown lock files retain them in preview and real runs, including a fresh check after sizing. Packages remain protected except the exact new Teams WebView profile Cache, Code Cache and GPUCache leaves during automatic clean; user exclusions still win. Profile discovery is one level, capped at 128 directories with a two-second checkpoint budget, and discards incomplete results. Locked by `tests/AppCacheSafety.Tests.ps1`.
- `~/.gitconfig.lock` is never deleted: Git holds it while it writes the config, and neither age nor an idle git process proves the write is over.
- Verify cleanup and uninstall changes with dry-run first; tests must not need a real UAC prompt.
- Tree and config-folder removal deletes each directory non-recursively (`[IO.Directory]::Delete($path, $false)`). `Remove-Item` without `-Recurse` on a folder that gained entries after the walk prompts to delete them, and a Yes removes unvalidated content. Locked by `Never deletes a folder recursively when it gained entries after the walk` in `tests/Core.Tests.ps1` and its config-folder twin in `tests/Install.Tests.ps1`.
- Content cleanup rejects a junction root or ancestor. Bind paths to Windows volume/file IDs before enumeration and sizing, and recheck at removal; a replaced directory is not the reviewed directory. A leaf junction may be unlinked without traversing its target. Unknown identities and incomplete walks keep the target. Locked by `tests/CleanupBoundary.Tests.ps1`.
- A missing whitelist file is empty; unreadable metadata or content retains every target. Read its literal filename, including brackets, with terminating errors. Never turn unknown user protection into an empty list. Locked by `tests/CleanupBoundary.Tests.ps1`. Whitelist and `purge_paths.txt` lines are read as UTF-8 (BOM aware, UTF-16/UTF-32 too) through a shared-access `FileStream`, written as UTF-8 with BOM, and normalized by `ConvertFrom-SwListEntry`: enclosing quotes removed, `/` to `\`, `~` to the profile, `%VAR%` expanded (undefined stays literal; for the whitelist the unexpanded spelling is kept as an extra pattern, so a real folder named `%NAME%` stays protected). An entry that expands to nothing usable adds no search path. A `*`/`?` entry also protects what is below it; `[` and backtick entries stay exact. Locked by `tests/WhitelistParsing.Tests.ps1`.
- A literal directory whitelist entry, including names containing brackets, covers its descendants but not prefix siblings. Check literal spelling before interpreting wildcard syntax. Every canonical whitelist row keeps its pattern, literal root, prefix and wildcard flag associated; mixed-rule sink regressions live in `tests/CleanupBoundary.Tests.ps1`. Native owner commands resolve their actual cache root, honor root and descendant exclusions, and recheck before mutation; an unknown root or failed owner command never falls back to direct deletion. Docker builder pruning stays off automatic cleanup because its remote or VM roots cannot be constrained by the local whitelist. Preserve Gradle transaction locks.
- Purge excludes `.idea`, scopes generic artifact names to the matching build ecosystem, and keeps Git-tracked content and nested repositories. Discovery and the final post-sizing guard use the same policy, literal case-insensitive Git pathspecs and isolated Git environment. A failed probe keeps the candidate. Locked by `tests/PurgeBoundary.Tests.ps1`.
- Uninstall sizes come from the registry `EstimatedSize` (KB); a value over 10 GB is checked against the measured `InstallLocation` and the measured size wins when it is at least 10x smaller. Duplicate uninstall entries merge, but never across two different install folders, and selection is keyed by registry key or package name, not display name.
- `sw uninstall` runs each uninstaller once, as registered (MSI, Inno and NSIS flags only when detected), and sends the leftover install folder to Recycle Bin only when `Test-SweeprLeftoverOwnership` accepts it after the uninstall key is gone. A drive root, the profile or its standard folders, `ProgramData`, `Program Files` and `Windows` are never leftovers, and neither is a Steam library: its root (a folder with a `steamapps` child or `libraryfolder.vdf`, the Steam client's folder included), `steamapps` or anything in it outside one game's `steamapps\common\<Game>`. Registered install folders containing game-library or emulator content stay out of leftover removal. Check public folder and GOG/Steam file markers at the root and immediate children with complete bounded visibility; unknown or redirected children retain the folder. Keep registered directory identity and display-size measurement independent of content retention, so protected content cannot collapse distinct registrations during merging. The content predicate runs in preview and the final ownership guard, while ordinary installs and single Steam games remain eligible. Store packages Windows depends on (Store, App Installer, Windows Security, Game Bar and other `Microsoft.Windows.*` packages) are not offered. App-cache v6 invalidates v5 identities and protected Store rows. Re-read the exact Store package identity and both metadata/sparse-manifest eligibility at preview and the final removal boundary; unknown package inventory retains the target, while an unreadable manifest preserves the existing discovery policy. The exact Proton Pass 1.37.0 / Proton AG / Update.exe `--uninstall -s` registration uses its matching registered `--uninstall` command; do not retry uninstallers or generalize this exception. Locked by `tests/Uninstall.Tests.ps1`.
- Registry uninstallers retain `Start-Process -Wait` descendant tracking in a cancellable runspace with a fixed 30-minute ceiling. This is a conservative wait bound, not an idle detector or user setting. Timeout stops the batch, preserves leftovers and leaves the vendor running; registration disappearance alone never proves completion. Unreadable registration remains installed. Cleanup exceptions cannot replace timeout/cancellation and advance the batch. `tests/UninstallWait.Tests.ps1` uses real disposable parent/child processes to check normal exit, descendant waiting and survival on timeout/cancellation; `tests/Uninstall.Tests.ps1` locks the batch stop after registration disappears.
- Uninstall leftovers use the dedicated shell `ITransferSource.RecycleItem` operation through `Remove-SafeItem -Recycle`. Never fall back to permanent deletion when recycling fails. Preview and the post-sizing guard independently verify complete installed-app ownership; preserve same, parent or child shared locations and unknown inventories. Recheck root identity and protected descendants after sizing, keep dry-run read-only, and do not count recycled bytes as freed space. Locked by `tests/SwFileOpsRemove.Tests.ps1`.
- `Test-SwProtectedPath` refuses secret-store segments (`Microsoft\Credentials`, `Protect`, `Crypto`, `Vault`, `SystemCertificates`, `Start Menu`) for every command, and during `sw clean` also key folders (`.ssh`, `.aws`, `.azure`, `.kube`, `.docker`, `.gnupg`), browser profile stores and `.claude` / `.codex` transcripts. `GetFullPath` already expands 8.3 short names (`C:\PROGRA~1`) and trailing-dot aliases of a protected tree, and those cases pass on code that predates final-path resolution; existing paths also resolve to their final spelling so a junction or symbolic link into a protected tree is refused, and a path that exists but cannot be resolved counts as protected; nonexistent candidates keep the lexical answer so planning works. A whitelist root that is itself a junction is matched in both its typed and final spelling, and a candidate is checked against the whitelist and the protected rules in both spellings; otherwise moving `%USERPROFILE%\.cargo` to another drive would delete the protected cache, and a linked `Microsoft\Credentials` or `.ssh` folder would lose its segment guard. Clean never targets Zoom `data`, Teams databases and storage, Recent items and jump lists, Office and Outlook file caches, sync-client folders, cloud CLI credentials, installed toolchain packages (Stack `programs`, Cabal `store` and `packages`, Hex `packages`), Spotify `Data` and `Storage`, or dumps and logs at the profile root. Locked by `tests/Protection.Tests.ps1` and the `Test-SwProtectedPath` cases in `tests/Core.Tests.ps1`.
- System cleanup does not stop FontCache or Windows Update for targets the Windows path policy refuses. Preserve service state instead of weakening that policy. Owner cache previews list the actual root without estimating whole-store savings for selective pruning; real-mode statistics use only a complete before/after measurement of the same root. An unmeasured successful owner command is activity, not proof the system was already clean. Locked by `tests/CleanupTargets.Tests.ps1` and `tests/Clean.Tests.ps1`.
- Error reports keep seven days by the newest creation/write time throughout each complete report, not the WER collection directory's timestamp. Recheck bounded complete visibility after sizing, and retain recent, redirected or unreadable reports. Sublime caches in Local and Roaming use the shared owner guard. Clean preserves Adobe Team Projects state at discovery and the shared clean sink, including parent sweeps; it is not proven disposable media cache. Locked by `tests/AppCacheSafety.Tests.ps1`.
- Disk optimization reads target-volume health before writing, keeps a known Warning/Unhealthy target, and requires external power for battery-equipped machines. Unknown power retains the drive; a complete empty battery inventory allows a desktop. A failed physical-disk inventory must still query the target volume independently. Unknown health is not a critical fault, and raw startup registration counts are not health failures. Locked by `tests/Optimize.Tests.ps1`. Status aggregates capacities only after every present system battery is known; empty bays are excluded and cycles describe the oldest pack when every count is known, independently of whether capacities are comparable. Unknown capacity never implies Healthy from cycles alone; preserve independent cycle warnings and a known system condition.
- `sw optimize` does not reset Winsock or rebuild the Search index, icon, font or Store caches: each drops state the user has to rebuild or reconnect for little gain. Locked by `tests/Optimize.Tests.ps1`.

## Compatibility

- The target is Windows PowerShell 5.1 on Windows 10 and 11. CI runs Pester under both Windows PowerShell 5.1 and pwsh 7; code that only works in pwsh 7 (`??`, `?.`, ternary, `-Parallel`) is a bug.
- Keep scripts ASCII or UTF-8 with BOM; Windows PowerShell 5.1 reads BOM-less non-ASCII text through the legacy code page.
- Go: the toolchain is pinned once, by `toolchain` in `go.mod`, and every workflow reads it through `go-version-file`.
- Analyze keeps every directly browsable child through live completion, cache returns and filtering. Recursive child summaries may remain bounded, but entering one must refresh it before claiming complete results. Restoring a selected path also clamps its viewport. Scan-time path indexes are invalidated after reorder, deletion, cancellation and completion; the existing display tick batches sorting/filtering without dropping completed results or cache updates. Locked by `cmd/analyze/directory_browsing_test.go` and `cmd/analyze/live_update_test.go`.
- Analyze registers scan identity before asynchronous dispatch and accepts only the current request, including when two requests use the same path. A deletion in progress ignores further action keys while retaining quit. Locked by `cmd/analyze/lifecycle_test.go`. Its Windows recycle guard also checks protected descendants and path identities immediately before the sink; incomplete walks keep the selection. A directory name alone is not proof it is cleanable; retain only explicit cache-tag evidence for that hint.

The installed `.cmd` launcher keeps PowerShell's `-File` invocation. That call binds `--debug` to the router's common `Debug` parameter; translate it back into the existing command arguments before loading modules, and suppress PowerShell's own debug stream. The native launcher uses quoted argument literals with `-Command`. Verify both call shapes create a fresh session log; `tests/Router.Tests.ps1` locks them.

Parsed command arguments are data: do not strip literal quote characters a second time. Propagate native TUI exit codes and reset stale native status for help-only calls. Status proxy rendering never falls back to raw environment or registry values, which may contain credentials.

## CI

- `Check`: `gofmt -l` must be clean, PowerShell syntax must parse, golangci-lint is pinned and advisory until its existing findings are fixed. CI never commits on its own.
- Run `actionlint` on workflow changes before pushing; a step's `shell:` cannot read the matrix, which GitHub rejects before any job starts.
- `Validation`: Pester on both PowerShell versions, Go tests, binary build, security checks.
- `scripts/test.ps1` requires Pester's explicit passing result with at least one passed test. Missing results, empty or entirely skipped suites and failed Go probes are not success; only an explicit `-NoGo` skips Go. Locked by `tests/TestRunner.Tests.ps1`.
- Actions are pinned by commit SHA.

Installer copies merge known source files without clearing shared destination directories. Reject unrelated nonempty roots and linked roots or ancestors. Keep the installer itself in copied installations. Whenever adding a shipped file, update `Get-SweeprInstallNestedFiles` and run the install inventory test, including documentation-only changes. Source installation and update fetch release tags so native source-equivalence checks can use them; changed native source still requires Go.

## Release

Read [RELEASE.md](../RELEASE.md) before any release work. In short:

- Tags are `V<version>-windows`; a version with a pre-release segment publishes a prerelease. The version lives in `VERSION` and `lib/core/version.ps1`; bump both together.
- The workflow creates a draft; the maintainer checks the assets and publishes it. Releases are not code-signed.
- `scripts/build-release.ps1` produces every asset and calls `scripts/write-checksums.ps1`; `SHA256SUMS.txt` must list the zip and both TUI executables, since `lib/core/tui_binaries.ps1` refuses a download it cannot match and never falls back to building after a mismatch.
- No package-manager manifests are kept in the repository; none is published. Recognising winget and Scoop installs in `sw update`/`sw remove` stays as described above.
- Releases, tags and package-manager submissions need the maintainer's explicit go-ahead.
